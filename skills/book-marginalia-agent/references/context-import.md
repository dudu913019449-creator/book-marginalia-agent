# Portable reader context import

Use this reference when a reader says that ChatGPT, Claude, Gemini, Copilot, a local model, or another long-used AI already understands their history better than this agent.

## Boundary

This is a user-mediated export, not an account integration. Never claim direct access to another AI's memory or chat history. Do not ask for credentials, API keys, OAuth access, or a complete conversation archive.

The safest useful artifact is a short Markdown context packet generated by the reader's existing AI, reviewed by the reader, and stored only in the reader's private local vault.

## Export prompt

Translate this prompt into the reader's language when useful. Keep the structure and safeguards.

```text
Based only on what I have explicitly told you in our prior conversations and any memories you are allowed to use, create a Reader Context Packet for a personal book-marginalia agent.

Requirements:
1. Do not invent missing biography or infer sensitive traits.
2. Separate confirmed facts, your inferences, and uncertainties.
3. Exclude passwords, account details, contact details, medical data, financial data, and other information unnecessary for reading commentary.
4. Focus on:
   - important experiences and turning points;
   - current projects and responsibilities;
   - values, tensions, and recurring questions;
   - decision patterns and preferred kinds of challenge;
   - reading interests and commentary preferences;
   - topics that may genuinely connect a passage to my life.
5. For each item, give a compact source description such as “recurring conversations about work” rather than exposing full chat text.
6. End with a section called “Needs my confirmation or correction”.
7. Return Markdown under 1,500 words.
```

## Review before import

Treat the returned packet as an AI-authored draft. Before saving:

1. Summarize the categories it contains without adding new claims.
2. Flag sensitive, speculative, contradictory, or overly broad statements.
3. Ask the reader to edit, remove, or explicitly approve the packet.
4. Accept “确认导入” or an equally clear instruction as approval of the reviewed version only.

If the reader provides corrections, update the draft before asking for final approval. Never treat silence as approval.

## Storage and provenance

Store an approved packet under:

```text
memories/imports/YYYY-MM-DD-<source>.md
```

Record:

- the source AI or assistant name supplied by the reader;
- the local import date;
- `Status: reader-confirmed`;
- a reminder that the packet is a reviewed AI synthesis rather than raw primary evidence.

When using the packet later, prefer one directly relevant item and cite the imported filename. A reader correction always overrides an older imported statement.

## Failure behavior

- If the packet mixes facts and inferences, reorganize it and ask for confirmation.
- If it contains credentials or unnecessary sensitive data, do not repeat those values; ask the reader to remove them.
- If it is too generic, import nothing yet and ask the existing AI for concrete, source-labelled context.
- If two imports conflict, surface the conflict instead of silently choosing one.
